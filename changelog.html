v1.3.0

2026-11-09V3 识别升级版

更新摘要

  • 识别引擎升级：rapidocr-onnxruntime 从 1.2.3 升到 1.4.4，压在半透明占比条上的小字号数字识别明显更稳。
  • 修复 1.4.x 下「局部补读」整条失效：1.4 起 read_line 返回 (text, score) 二元组，
  • 数值自洽性核对：修复后战绩页左 5 人击杀合计 14、右 5 人 26，与页面比分一致，逐行占比也对得上。
  • Python 支持范围调整为 3.11 / 3.12：1.4.x 只发布到 3.12，CI 矩阵同步去掉 3.13，
  • 演示数据补上主教练：seed_demo_data.py 灌完数据后，教练档案页不再是一片空白。
  • 路由审计脚本区分空态：正常空状态（#content .empty）不再被判为失败。

升级说明

  • 安装包与免安装包不内置 OCR 组件（体积原因），首次使用仍在「识别引擎」条里点一键安装；
  • 已经装过 OCR 组件的用户：增量更新只替换程序文件，不会动已装好的 site-packages，
  • 源码用户请重新执行 pip install -r requirements.txt（OCR 依赖从 1.2.3 升到 1.4.4）。
  • 仍在 Python 3.13 上跑源码的用户，需要降到 3.12 或改用安装包。

v1.2.0

2026-11-09

新增：OCR 组件检测与一键安装（主 OCR / Mimo 精读 / ffmpeg）

  • 截图与录屏两页顶部新增「识别引擎」条：主 OCR（rapidocr）、Mimo 精读、ffmpeg 三项独立检测，缺哪个就在哪一行给按钮和原因，不再只在上传时报错。
  • 安装走服务端后台任务（GET/POST /api/ocr/install）：pip 先走清华镜像、失败自动回官方源；主 OCR 装 requirements-ocr.txt，Mimo 再下载约 2 GB 模型（官方源失败切 hf-mirror）。
  • 进度可见：百分比 + 当前步骤（正在下载 torch / 正在下载模型 1.2 GB / 3.1 GB），切页面不会中断；右下角常驻进度卡，装完给「已装好」提示并自动收起。
  • 完成后不用重启：状态接口重新探测，页面自动刷新并把「Mimo 精读」选项从禁用改为可选。
  • 装之前先看磁盘：主 OCR 需 1 GB、Mimo 需 4 GB，空间不够按钮直接禁用并说明可清理录屏缓存或换盘；安装中重复点击会返回 409。
  • 没装 Mimo 时选「Mimo 精读」不再白等：上传时自动退回主 OCR 并提示，装好后可「重新识别」再跑一遍。
  • ffmpeg 缺失时给 winget install Gyan.FFmpeg 与手动配置指引，并支持「重新检测」。
  • 发版清单补上 requirements-mimo.txt（此前安装包里没有，一键安装会直接失败）。
  • 修复发布脚本在 3.13 构建机上装错二进制轮子（内置运行时是 3.12），打包冒烟测试不再因 pydantic_core 失败。

重构：截图 OCR / 录屏 OCR 两个完整页

  • 原来的两页只有「上传 + 列表」，七张截图和录屏规范都挂在外部文档链接上，教练得先跳出去看规范再回来。现在规范直接嵌在页内：
  • 两页都加了「去另一个页面」的直达按钮：截图页提示还要录屏，录屏页提示还要七张截图，不会做到一半迷路。
  • 截图识别结果改成按组的卡片：N / 7 页 · 缺 发育、团队 徽标 + 七段覆盖度色条，缺哪页直接点名；每组仍可展开看逐页明细与提示。
  • 录屏列表改成带进度条的卡片：状态徽标（识别完成 / 识别中 / 失败）、进度百分比、采样与计时帧、双方击杀、证据帧、提示数；识别完成后可直接把报告挂到某一局（复用 /api/channels/{id}/video），不用再手工导出 JSON。
  • 上传区统一成虚线投放区（选择文件后显示已选文件名与数量），录屏的帧率 / 识别方式与原上传按钮排在同一行。

重构：采集页按「营地连接 → 拉取对局 → 截图/录屏 OCR → 对局审查」组织

  • 顺序按教练的实际动作重排：先连接，再拉取；拉取结果按「待同步 / 已进统计 / 营地无详情 / 待审查」分桶，后三桶折叠收起。
  • 出现「营地无详情」时，列表顶部常驻一条琥珀色提醒（多少局、为什么、怎么办），并直接给「补录一局」「去截图 / 录屏」两个动作；超过一个月的局整桶折叠，不再占篇幅。
  • 新增常驻的「截图 / 录屏 OCR」区块：两个窗口并排显示识别状态与数量，截图可就地选择并上传识别，录屏入口与拍摄要求同屏可见，各自带「完整页 →」。
  • 「对局审查」按来源拆成两组并排上下：王者营地（字段齐全、自动进入正式统计、不走人工审核）与 截图 / 录屏 OCR（OCR 可能有缺，必须逐条确认后才能保存），空组收成一行说明。
  • 视觉收敛：卡片圆角/描边/阴影统一，标题加 3px 主题色点缀，正文内边距统一 22px，按钮统一 32px 高，小字统一 11.5–12px，页面主标题从 34px 收到 26px，筛选条与空状态更紧凑。
  • 查看缺失值审查 的定位改为按标记查找，区块重排后不会滚错位置。

优化：采集页一屏工作台 + 老对局补录入口

  • 首屏顺序改成「下一步条 → 拉取对局 → 缺失值审查 → 营地连接」：1920×960 下「拉取对局」从 y=902 提到 y=310，列表直接在首屏可见。
  • 「下一步」卡在授权正常、选手已绑定时压成 78px 的一条（右侧只留「今天拉取过」），不再占掉五分之一屏。
  • 「营地连接」在已授权且有选手时折叠成一条（昵称 / 授权时间 / 选手数 + 展开管理），要改白名单或重新扫码再展开；授权失效时仍默认展开并置顶报警。
  • 新增「补录一局（截图/录屏）」：营地拿不到的老对局可直接在工作台建一条审查记录（填日期 / 训练组），建完跳到「截图 OCR」，新建的通道在下拉里预选，挂完截图即清除。
  • 拉取列表里出现「营地无详情」的局时，提示行同时给出「直接补录一局」和拍摄规范链接，不用先跳出去看文档再回来。
  • 修掉一个隐患：查看缺失值审查 原来按 .section 下标定位，区块重排后会滚错位置，改成按标记定位。

新增：教练版《老对局补录》说明页

修复：营地只提供最近一个月的战局详情（-30457）

  • 营地详情接口对一个月前的局返回 -30457 暂不支持查看一个月前的战绩详情。现在拉取列表里这类局直接标「营地无详情」并取消勾选，不再让人勾上后白等；后端 /api/camp/list 增加 campDetailAvailable 标记。
  • sync_entries 对超期局不再发详情请求，接口返回 -30457 时记为「营地无详情」而不是失败，也不会触发「连续 5 局失败」中止。
  • 同步结果把「营地无详情」与「没拉全」分开统计：前者提示改用截图/录屏兜底，后者仍留在列表里可重试。

修复：营地同步「显示同步了 127 局，实际一局没进」

  • 页面提示改用真实入库数：只有后端回报写入正式统计 / 待审查的局才计入，一局没写入时按失败提示并给出原因，不再拿「勾选数」当成功数。
  • 同步全程可见：拉取阶段显示已翻页数与已拿到局数，拉详情 / 写统计阶段显示 已处理 / 总局数 与当前对局；卡片进度条外加右下角浮动进度，滚动到列表深处也能看见。
  • 同步结束后在卡片里留一行结果（进入正式统计 / 待缺失值审查 / 没拉全可重试），不必再翻上面的提示。

  • 后端兼容旧版 tools/camp_sync.py（没有 on_progress 参数时退化为无进度拉取）——安装包只升级主程序、tools/ 还是旧版时，同步会因 TypeError 整批中断，这就是本次 127 局一局没进的直接原因。
  • sync_entries 单局失败不再打断整批：记录失败原因后继续，连续 5 局失败才停下；中断时已拉到本机的详情照样建通道入库。
  • 没有拉到详情的局不再建空审查记录（避免缺失值审查被几十条无面板记录堆满），按「没拉全」留在拉取列表里。
  • _camp_ensure_channels 增加逐局结果（items），供前端回填「已进统计 / 待审查 / 失败」。

v1.1.0

2026-11-08

更新摘要

  • 平台收成 V3 单应用：根路径直接进入，旧链接自动跳转，采集 / 导入 / 分析 / 赛训在同一进程。
  • 新增赛训闭环：训练计划 → 训练课 → 目标判定 → 报告 / 周报，配套赛训看板与统一指标层。
  • 新增跨局分析：多局按统一口径重算，10 张结论卡、分路对位与逐局对照 CSV。
  • 新增选手档案：逐人档案卡，按认领状态 / 分路 / 关键词筛选，点卡片进入个人页。
  • 新增战队风格 / 阵容 / 训练：四项同池分位、五人组与轮换、按对手汇总训练课。
  • 营地授权失效检测；对局标签与分路统一；自动认领存疑局只交给教练。
  • 新增 Windows 安装包、无黑窗启动与优雅停服；官网升级为产品站。
  • 新增首次打开页：空库时给三条起手路径（扫码采集 / 看示例 / 导入），不再是一页空白首页。
  • 新增旧数据一键搬迁：自动发现旧目录，整库复制（回放与录屏可选），失败不留残留、可重试。
  • 修复安装版采集页 500：tools/ 下的营地同步与回放解码模块漏出发布清单，补齐并有测试兜底。
  • 修复训练纪录页空数据崩溃；V3 写接口非法 JSON 返回 400。

一个入口：V3 单应用

  • 根路径直接进入 V3；V2 的 40 条路由改成 APIRouter 并入 server.py，不再挂第二个 app。
  • 全站只保留 V3：27 条分析路由统一到规范前缀 /api/v3/*；旧版模块名、环境变量、目录与前端调用统一改名，旧前缀不再保留。
  • 旧版时间轴构建模块 → replay_timeline_build.py（出装时间轴，V3 仍需）；V3 未使用的时间轴 API、预览脚本与历史快照移出工作区。
  • 旧环境变量与目录 → ANALYSIS_BUILDS / BUILDS_DIR / data/builds；web/capture-guide/ 因采集页与 collection_contract.py 依赖而保留。
  • 演示数据不再另起旧版只读的 v3/serve.py：8773 现在跑完整 server.py 单应用，采集 / 导入 / 分析链路与真实工作台一致，靠 KPL_DATA_DIR 隔离数据，采集页不再提示「采集接口未挂载」。
  • /api/mode、/api/demo/start 为唯一入口，演示标识为 training-data-v3。
  • frontend-v2-rebuild/ 改名为 v3/；V1 /studio、V2 8771 独立入口和 启动赛训数据V2.bat 退役。
  • 写操作会通过 server.py 中间件刷新 V3 分析快照；/v3、/studio、/analysis 统一 302 到根路径。
  • V3 写接口遇到非法 JSON 请求体时统一返回 400，不再抛 JSONDecodeError 变成 500。
  • 发布包与 Docker 镜像纳入 v3/；启动入口和文档同步改为 http://127.0.0.1:8766/。

赛训闭环

  • 新增「训练计划」：按训练组、对手与日期排期，写训练目标；顶部赛训看板集中展示近 8 周训练负荷、目标达成环、训练节奏热力、目标绑定 / 复盘 / 对局关联覆盖率与最近训练课。
  • 新增「训练课」：按绑定关系、日期 + 对手、日期 + 训练组依次关联对局，也可手动挂局；带对手简报（最近交手 / 常用英雄 / 禁用习惯 / 关键选手）。
  • 训练课可写训练目标、勾选出勤、保存赛后复盘；标记已复盘后计划自动完成，出勤写入训练课报告。
  • 训练目标支持绑定指标 + 目标值 + 达成 / 部分达成 / 未达成状态；绑定已接入指标后，保存时自动判定，报告直接显示目标、实际值与达成表。
  • 报告导出：训练课生成 A4 报告，报告库生成训练周报（带上周对比），均可导出 PNG 或打印 / 保存 PDF。
  • 新增赛训指标层：metrics_registry.py 登记指标口径，metric_service.py 统一查询训练课 / 周指标；训练课页与周报读同一份结果，缺数据的指标返回原因而不是 0。训练过程为主，胜率与场均时长只作对局上下文。
  • 顶部「待处理」汇总待确认、战队待命名、旧名单未迁、训练课待复盘和历史对手 ID 未映射。
  • 历史 enemy_team_id 可在待处理收件箱映射到当前战队；映射后相关对局、训练课和周报一起生效。

跨局分析

  • 新增「跨局分析」：默认纳入全部已确认对局，按当前筛选一次重算；结论基于总体分布、分层与效应量，不随分页或单局明细变化。
  • 固定 10 张结论卡：分层基准、波动来源、下限风险、训练效应、水平变点、打法体系、体系适配、优势归因、领先守成、复盘队列；每张卡先给问题，再给结论与样本口径。
  • 新增分路对位平均分差图与逐局对照 CSV；置信分级随样本量变化，小样本会降级计算方法或标注精度，不硬下结论。

选手档案

  • 新增「选手档案」：逐人档案卡，头像、位置、局数、胜率、KDA、MVP 与参团一眼可比；点卡片进入个人页看同位置分位、关键局与搭档。
  • 支持按认领状态（已认领 / 待认领）、分路与关键词筛选；待认领昵称可直接从档案页命名，认领后名单、位置与对比按选手累计。
  • 「名单与状态」保留队伍视角；「选手认领」继续负责身份维护，档案页只做只读展示与入口。

分析与导航

  • 战队聚焦训练组和全队节奏，选手聚焦个人状态与搭档，英雄聚焦分路和出装，BP 聚焦对手与阵容，对比按同分路重算双方样本。
  • 五个分析模块默认使用已入档营地记录，可手动纳入其他来源。营地原始面板和回放分析单列来源，并支持按开赛日期筛选。
